Colour inside a boundary, black and white outside it

ფერი საზღვრის შიგნით, შავ-თეთრი გარეთ

ამ გვერდის ძირითადი ტექსტი ჯერ ინგლისურადაა. სათაურები და რუკის ინტერფეისი ქართულადაა; სტატიის თარგმანი მოგვიანებით დაემატება.

The effect is simple to describe and awkward to build: satellite imagery in full colour inside a microzone, desaturated everywhere else, dissolving across the boundary rather than stopping at it.

24 August 2026 · build note

Mapbox GL JS has no way to clip a raster layer to a polygon. That single fact rules out the obvious approaches, and it's worth walking through why, because each one looks like it should work.

The inverse mask

The standard trick for isolating a region: build one polygon whose outer ring is a generous local bounding box and whose holes are your boundary, then draw it opaque above the imagery. Everything outside the hole is covered; the region shows through. It is genuinely the right answer when what you want is region visible, surroundings suppressed.

It cannot do this job, though, because a fill can only add colour on top. It can hide the imagery outside the boundary, but it cannot make that imagery render differently — and grey at partial opacity is not desaturation, it's a tint. The green bleeds through and the outside reads as murky rather than neutral.

Two raster layers

So: colour imagery at the bottom, a desaturated copy of the same source above it, and punch a hole in the top one. Except that punching a hole in a raster layer is the thing that isn't possible. Reversing the stack doesn't help — whichever layer needs the hole, it's a raster.

The clip layer

GL JS v3 added a clip layer type, which sounds exactly right. Its clip-layer-types accepts model, symbol and fill-extrusion. Not raster. And it clips content inside the clip polygon, which is the opposite of what's wanted here.

Two synced maps

Two map instances, one desaturated and one in colour, the top one masked to the boundary with CSS. This does work, and it's the approach to reach for if the shape has to be interactive. The costs are a second WebGL context, camera synchronisation on every frame, and a mask that has to be reprojected to screen coordinates as the camera moves — for a feathered edge that means regenerating an SVG or data-URI mask per frame.

What the piece actually does

The boundaries don't move relative to the world, so the mask doesn't have to live in screen space at all. Do the cut once, in pixels, and hand the result back as geography:

  1. Request the zone's bounding box from the Static Images API — full-colour satellite, up to 1280 px a side at @2x.
  2. Draw it into a canvas.
  3. Composite the boundary path over it with destination-in, so only what falls inside the shape survives.
  4. Add the canvas as an image source with the bbox corners as its coordinates, above a globally desaturated satellite layer.

Mapbox then reprojects and scales that image like any other raster. No second context, no per-frame work, no CSS masking.

Two details that matter

The pixel mapping has to be Mercator, not linear in degrees. A static image comes back in Web Mercator, so the y coordinate of each boundary vertex is log(tan(π/4 + φ/2)) scaled across the box, not a straight interpolation of latitude. Getting this wrong puts the mask a few per cent off the imagery — invisible in the middle of the shape, obvious at the edge.

And the feather should not come from ctx.filter. It's the natural choice — filter = 'blur(80px)' before the composite — but it's missing in Safari before 17, and when it's missing the code doesn't fail, it silently produces a hard edge: precisely the artefact the technique exists to avoid. A drop shadow does the same job everywhere. Park the path off-canvas, offset the shadow back into frame, and use the blurred silhouette as the alpha channel.

The implementation is buildPatch() in assets/scroll.js. Its two knobs are PATCH_PAD, the margin around the zone so the blur has room to spill, and PATCH_FEATHER, the blur radius as a fraction of the patch's short side.
